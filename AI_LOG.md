# Журнал работы с ИИ

- **Инструменты.** Claude Code (Claude Opus) — исследование базы и предметной области, черновики словарей, код, тесты, документация. В рантайме — Jev Choice (выбор из ряда) и эмбеддинги bge-m3 через OpenRouter.
- **Проверено.** Каждое правило словарей — подсчётом строк базы (`строк_в_базе`); все оставлены `предложено`, утверждает специалист. Сходство без БД сверено с `similarity()` PostgreSQL и закреплено тестом. Цена модели — по счётчику ключа, а не по токенам.
- **Исправлено — ложные «найдено».** АС 240/39 → 240/32, ТМЛ 50 → ТМЛ 120, «d=200» читалось как 500. Причина: непрочитанная hard-характеристика молча пропускалась. Добавлена метка «не проверено».
- **Исправлено — модель.** Верные, но неуверенные ответы (0,84–0,89) роняли hit@1 до 0,85. Теперь неуверенный ответ равен отсутствию ответа.
- **Исправлено — интерфейс и загрузка.** «свет» ставил «Оповещатель световой» выше «Светильника». `positions load` без ключа стирал векторы из дампа.
- **Отклонено.** TF-IDF с лимитом в 50 кандидатов: мог отсечь верную строку, взяты все строки категории. Графовая БД для карточек: «аналог» не транзитивен, хватает двух таблиц PG. Ожидание «не найдено» для «ИБП 12В для улицы»: в базе есть строка 1541.
- **Честность замера.** Группа words улучшена по её же ошибкам: 4 → 12 из 12. Поэтому до прогона записана отложенная группа held_out: 3 из 8, после правок 7 из 8, пределы описаны.
- **Оставлено человеку.** Подсказки редактора знаний не применяются сами. Допуск мощности ±1 снимает расхождение с карточкой, но ломает контрольный запрос t6 — решает специалист.

| Проверка сечений на реальных строках | разобрать `сечение_жилы` по всем категориям | найдены ложные «найдено»: АС 240/39 → 240/32, ТМЛ 50 → ТМЛ 120, КПСЭ 2×2×0,75 → «та же» 2×2×0,5, «3×2,5+1×1,5» → «та же» 3×2,5, «d=200» у воздуховода читалось как 500. Причина — непрочитанная hard молча пропускалась. Добавлены метка «не проверено», отклонение составных формул, экстракторы витой пары и сечения воздуховода, 6 запросов в контрольный набор |
| Модель в рантайме (Jev Choice) | дочитывать hard без экстрактора выбором из ряда; «не указано» — тишина, неотвеченное — тоже | прогон по контрольному набору вскрыл три ошибки: (1) метка «та же» требовала, чтобы модель была спрошена, — отклонено, достаточно прочитать у обоих; (2) «ТМЛ 300» вне ряда модель честно не выбирала, а поиск считал это «не указано» и находил ТМЛ любого размера — добавлен вариант «не из списка», уверенный не-«не указано» делает находку «не проверено»; (3) после этого неуверенные верные ответы (0,84–0,89) тоже стали «не проверено», hit@1 упал до 0,85 — неуверенный ответ и сбой модели теперь равны отсутствию модели, закреплено тестами. Тип наконечника (кольцевой / штифтовой / гильза) сделан hard после проверки 21 строки; марки ТМЛ/НШП/ГМ и АС 240/32 читает правило, не модель — дешевле и точнее |
| Запросы своими словами | группа words из 12 запросов (опечатки, числа словами, «на», без марки) — до правок 4 из 12; категория моделью из ближайших по написанию, soft и числа словами у запроса, правило «A на B» | после правок words 12 из 12, но правки делались по её ошибкам — поэтому дописана отложенная группа held_out до прогона: 3 из 8. По ней найдены ошибка разметки (h3) и пробел «сто на четыреста» — исправлены, 5 из 8; три оставшихся (жаргон, «пятая категория», «АС тридцать пять») оставлены и описаны. Отклонено: переводить словами записанные числа в цифры везде — «три жилы по два» неоднозначно, это читает модель. Порог 0,8 для чисел из строки введён после просмотра 105 ответов 0,8–0,9 |
| Эмбеддинги и судья | вектор запроса (bge-m3 через OpenRouter) для выбора категории и для кандидатов по смыслу по всей базе; модель-судья для того, что правила не решили | проба на категориях: «бесперебойник» → ИБП, «фонарь для улицы» → светильник, «насос», «болгарка» — честно «ни одна». Косинус несвязанных названий у bge-m3 — 0,3–0,4, поэтому сходство по смыслу пересчитывается от 0,5. Ограничения заданы кодом, закреплены тестами: отсеянное hard-правилом судья не видит; строка чужой категории проверяется правилами категории запроса и не бывает выше аналога; неуверенный ответ и сбой — как без модели. Тест вскрыл: судья видит только 10 лучших, остальные остаются «не проверено» — оставлено и описано. Итог: hit@1 0,92 → 0,97, misplace@1 0,07 → 0,00, held_out 5 → 7 из 8. В проде — та же модель локально |
| Подтверждение специалистом | графовая БД для связей «та же / аналог»; карточка по тексту запроса | графовая БД отклонена: «аналог» не транзитивен, обхода дальше шага нет — две таблицы PG. Ключ карточки — категория + характеристики, а не текст: «бесперебойник 12 вольт» попал в карточку «ИБП 12В». Эталон КСР при первой версии привязал воздуховоду фасонные изделия (толщина не прочитана) — правило ужесточено: эталон только при всех названных и совпавших hard. Идентификаторы карточек «прыгали» из-за `on_conflict` — сначала поиск, потом вставка. Строка истории адресуется источником и номером. Карточки не участвуют в оценке — без утечки ответов |
| Разбор запроса как категория магазина | все характеристики категории — указанные и «можно указать» с вариантами ряда; смена категории, выбор значения, «не указано»; поиск и карточка по исправленной структуре | выбор значения ограничен рядом и тем, что экстрактор принимает как своё (`accepts`), — иначе выбранное «1,5 мм²» не сравнилось бы с прочитанным; контракт модели не расширен: ей по-прежнему задают вопрос только там, где ряд — это сами значения экстрактора. Найдено при проверке: «экран» и «пожарное исполнение» сначала остались без вариантов — их экстракторы не помечены для модели, отсюда отдельный `accepts` |

В браузере: Enter после Escape брал выделенную строку скрытого списка — список теперь очищается при скрытии |
| Автодополнение: слово, категория, ранжирование наименований | дописывание по биграммам названий истории, категории по словам-признакам, наименования по доле триграмм запроса | на реальной базе «свет» давало «Оповещатель световой» выше «Светильника» — ранжирование по сходству строк заменено долей триграмм запроса и «начинается с запроса»; «ворота отк» дописывалось в «отказоустойчивости» — оставлены только слова, идущие после предыдущего; «кабель (прочий)» шёл выше набираемой «кабель контрольный» — начатые категории первыми |
| Редактор знаний специалиста | знания в БД релизами, черновик правок, проверка влияния, публикация с переразбором; подсказки из золотых карточек | подсказки не применяются сами — отметка по одной строке не правило; проверка влияния на примере показала цену: допуск мощности ±1 снимает расхождение с карточкой, но ломает контрольный запрос t6 — оставлено решать специалисту.
