# analog-search

Поиск аналогов материалов и оборудования по истории закупок: та же позиция, допустимый аналог с перечнем
отличий — или честное «не найдено» с причиной.

## Запуск

Рекомендуется запускать с ключом OpenRouter: только так работает полный поиск — правила + ИИ.

```bash
OPENROUTER_API_KEY=sk-or-... docker compose up --build   # рекомендуется: правила + ИИ
docker compose up --build                                # без ключа: правила и сохранённые ответы модели
```

Открыть http://localhost:8000 (поиск), http://localhost:8000/knowledge (правка знаний), http://localhost:8000/docs (API).

- **Без ключа** — только правила и сохранённые ответы модели, поиска по смыслу нет: hit@1 0,77 вместо 0,97
  (страдают запросы своими словами: «бесперебойник», «семь жил»).
- **Ключ в файл:** `cp .env.example .env` и вписать его туда.
- **База** при первом старте восстанавливается из `data/dump/analog.dump`; заново — `docker compose down -v`.
- **Параметры:** `POSITIONS_FILE=/path/file.xlsx` (другая история), `API_PORT=8080`, `DB_PORT=5444`.

## Допущения

- **Правила замен придуманы нами**, утверждает специалист: сечение кабеля — строго, камера — ±1 ступень
  разрешения, IP — «не хуже». Правятся на `/knowledge` без кода.
- **Цена в отбор не идёт** — она условная, только показывается.
- **Перевозка и погрузка** (108 строк) — не материалы и не оборудование, в выдачу не попадают.
- **Номера пунктов** («1.7.2)») срезаются, смесь кириллицы и латиницы в слове (`BВГнг`) приводится к одному алфавиту.
- **Составные позиции** («… в составе:», 138 строк) сравниваются по головному изделию.
- **Значения и расшифровки марок** — из ГОСТ, КСР, ОКПД2, ETIM и каталогов (`research/`), у каждой помечен источник.

## Локально

```bash
uv sync
docker compose up -d db                               # PostgreSQL 17 + pg_trgm + pgvector, порт 5434
uv run analog-search db init && uv run analog-search positions load
uv run analog-search serve                            # http://127.0.0.1:8000
uv run analog-search --help                           # остальные команды: search, decisions, knowledge, sources

uv run pytest                                         # тесты без БД; -m integration — с БД
uv run ruff check . && uv run ruff format --check . && uv run mypy   # линтеры и типы
uv run python evaluation/evaluate.py --llm cache      # метрики → evaluation/metrics_report.md (без ключа, ответы ИИ из кэша)
```

## Где что лежит

| Путь | Что |
|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | схема и шаги поиска, где ИИ / код / человек, хранилище и модели, стоимость, качество, ограничения и план |
| [AI_LOG.md](AI_LOG.md) | журнал работы с ИИ и время |
| `src/` | код по слоям: `domain` (правила и порты) ← `services` (сценарии) ← `repositories` (БД) и `infrastructure` (файлы, модели, источники) ← `app` (API, CLI, сборка); направление импортов проверяет `tests/test_layers.py` |
| `static/` | страницы поиска и правки знаний |
| `research/` | знания: `categories.yaml`, `attributes.yaml` (начальное наполнение БД), отчёт по базе, вопросы специалисту, промпт исследования `PROMPT.md`; `scripts/` — генератор yaml из базы |
| `src/app/search_config.py` | правила поиска: веса оценки, порог «не найдено», top-K, уверенность модели |
| `evaluation/` | контрольный набор `gold_queries.json`, `evaluate.py`, отчёт |
| `demo/decisions.json` | демо-решения специалиста → золотые карточки |
| `data/` | `positions.xlsx` (копия базы из задания), дамп БД, кэш ответов модели |
| `tests/` | тесты |
